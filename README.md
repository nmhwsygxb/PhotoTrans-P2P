# PhotoTrans-P2P

PhotoTransDrive 的浏览器版——**手机在外面也能下载家里电脑的文件**，免费、不装 App、浏览器直接用。

> ⚠️ **本版本为测试版（Preview / Beta）**：未经过更深层的验证，可能存在未知问题（网络兼容、稳定性、安全等）。请先在小范围评估后使用；使用中遇到任何问题请及时反馈，我们会持续修复。

---

## 怎么用（三步）

1. **改配置**：编辑 `config.json`，把 `share_dir` 改成你想共享的文件夹（模板见 `config.example.json`）
2. **启动**：双击 `start.bat`（家里用）或 `start_public.bat`（在外面也要访问）
3. **手机打开网址**：
   - 局域网：看命令行窗口打印的 `局域网` 地址（手机连同一 WiFi）
   - 公网：`start_public.bat` 窗口会打印 `https://xxx.trycloudflare.com` 网址

> 命令行窗口**不要关**，关了服务就停。

## 配置文件 `config.json`

```json
{
  "share_dir": "D:\\我的共享文件夹",
  "port": 8082
}
```

- `share_dir`：共享目录（不存在会自动创建 `share/`）
- `port`：服务端口（默认 8082，一般不用改）
- 首次使用可把 `config.example.json` 复制为 `config.json` 再改路径

## 两种模式

| 模式 | 启动脚本 | 适用 | 实测速度 |
|---|---|---|---|
| 局域网 | `start.bat` | 手机和电脑连同一 WiFi | **41 MB/s**（全速） |
| 公网 | `start_public.bat` | 手机在外面（4G/5G/移动网） | **1 ~ 1.5 MB/s** |

## ⚠️ 注意事项（请先读完）

### 1. 速度上限的真相：瓶颈是你家宽带的"上行"

实测同一条 10MB 文件：**局域网直连 41 MB/s，公网只有 1~1.5 MB/s**。
这不是 Cloudflare 隧道限速（[Cloudflare Tunnel 免费版本身不限速](https://cloud.tencent.com.cn/developer/article/2710363)），而是——**手机从外面下载时，数据要从你家电脑"上传"出去，你家宽带的上行带宽就这么多**（常见家用宽带上行只有 8~30Mbps）。
**任何方案**（WebRTC / frp / 自建中继 / 换隧道商）只要数据还在你家电脑、走这根光纤，**上限都一样**。想让外网下载更快，只有两条路：
- 提高家庭宽带的上行带宽（换套餐 / 加一条高上行线路）
- 把服务搬到有高速上行的服务器上（见下方"建议上服务器"）

### 2. 网址（URL）会变，运行期内固定

- **运行期间 URL 固定**：`start_public.bat` 用 `--retries 100` 让隧道掉线自动重连、进程不退出，**窗口开着 URL 就不变**。
- **重启后会变**：免费 quick tunnel 每次启动都是新 URL（无账号的 Cloudflare 特性）。
- **想永久固定 URL**：需要 ① 注册 Cloudflare 免费账号 ② 有一个自己的域名 ③ 用 named tunnel（命令行换成 `cloudflared tunnel --name ...`）。免费可行，但要自己操作。

### 3. 掉线自动恢复

- 隧道断了：`--retries 100` 自动重连，URL 不变。
- 本地服务死了：脚本每轮检查 8082 端口，没了会自动重启。
- 建隧道失败（偶发网络抖动）：脚本自动重试，直到成功（实测有超时后自动成功的记录）。

### 4. 手机浏览器兼容

- **文件下载不受影响**：走的是普通 HTTPS，任何浏览器都能下。
- **WebRTC（P2P 加速）是可选增强**：部分手机浏览器（如 VIA/某些 WebView）不支持 WebRTC，页面会自动跳过，**下载照常走中继**，不影响使用。
- 跨运营商打洞（移动↔电信/联通）实测会被运营商丢 UDP 包，P2P 连不上——**正常现象，不是故障**，下载不受影响。

### 5. 安全提醒（重要）

- 共享目录**没有密码**：任何人拿到网址就能下载里面的文件，而且网址可能被转发。
- **只把"愿意公开"的文件放进共享目录**，不要把整个硬盘/私人文件夹共享。
- 局域网模式（`start.bat`）同样没有鉴权，但只在本机 WiFi 内可达，风险小一些。
- 后续版本建议加：访问口令 / 一次性链接 / 目录白名单。

### 6. 免费隧道本身的性质

- 无账号 quick tunnel **没有 SLA/稳定性保证**（Cloudflare 官方说明），偶尔波动、偶尔需要重连是正常的。
- 家庭电脑关机/睡眠 = 服务不可达；这是自托管方案的固有特性。

## 建议：上服务器（让"快"和"稳定"都成立）

家庭宽带的小上行是外网下载慢的物理瓶颈。如果这个工具打算认真用，**最有效的升级是把服务放到一台有公网 IP + 高速带宽的服务器上**：

| 维度 | 家里电脑 | 云服务器（推荐） |
|---|---|---|
| 外网下载速度 | 1~1.5 MB/s（家宽上行瓶颈） | 通常 10~50 MB/s（服务器上行大） |
| URL 固定 | 每次重启变（除非自有域名） | 公网 IP 直连，或绑域名永远不变 |
| 可用性 | 关机/断电就没了 | 24 小时在线 |
| 成本 | 免费（已有设备） | 轻量 VPS 约 ￥30~60/月 |

**落地方式**（都免费/低门槛）：
1. **最简单**：把本项目代码放到 VPS，`python server.py` + `cloudflared`（或直接开 8082 端口绑域名），速度、URL、稳定性一次解决。
2. **更省**：文件不多的话，用 Cloudflare 免费静态托管（Pages/R2）放文件列表——但那就成了"网盘"，取决于你要不要文件长期托管。
3. 想保持"文件在自家"又提速：**提高家庭宽带上行**是唯一正解，其余都是绕。

> 结论一句话：**家里用（局域网）已经全速；外面用（公网）的 1MB/s 是家庭上行的天花板，不是代码能救的**。要认真用 → 上服务器或提高上行，二选一。

## 架构

```
[手机浏览器] --HTTPS+WS--> [Cloudflare Tunnel] --TCP--> [电脑 server.py:8082]
      |                                                         |
      |---------- WebRTC 打洞 (可选加速, 不强求) --> [电脑端 WebRTC] |
```

- **下载/信令**：浏览器 ↔ 电脑走 HTTPS（经 Cloudflare Tunnel 免费转发）
- **WebRTC**：同网络时直连加速；跨网/不支持时自动走中继，**不阻塞下载**

## 技术说明

- Python 服务：`server.py`（aiohttp + aiortc），依赖 `pip install aiohttp aiortc`
- STUN 用 Cloudflare `stun:162.159.207.0:3478`（**不要用 Google `l.google.com`**：境内被污染，srflx 查询静默失败，打洞必败）
- `cloudflared.exe`：下载 https://github.com/cloudflare/cloudflared/releases/latest → `cloudflared-windows-amd64.exe` 改名放本目录
- 启动脚本要点：`start_public.bat` 扁平化写法（Windows cmd 括号块易踩坑）；CRLF 换行；隧道用 `--retries 100` 自愈

## 与 PhotoTransDrive 的关系

- **PhotoTransDrive**：电脑端网盘（局域网直连 + 分享引擎）
- **PhotoTrans-P2P**：浏览器端下载（本仓库），手机零安装

两者互补：在家用局域网地址全速，在外面用 CF 隧道网址保底。
